# 复习提醒（艾宾浩斯主动复习）

复习提醒原本实现在浏览器扩展 vibe-reading 里（`src/utils/review/`、
`src/entrypoints/background/review-scheduler.ts`、独立复习卡片页）。现在整套
搬到后端：**调度、状态、Windows 通知、复习卡片与配置页面都由本服务提供**，
扩展侧只保留生词本与闪卡。

## 为什么放后端

- 状态本来就不在扩展里——`/api/vocabulary` 没有「上次推送时间」字段，扩展
  只能把 SRS 队列整个镜像到 `chrome.storage.local`，还得自己同步、自己判断
  「这个词复习过没有」。后端本来就是生词本的源头，直接在源头判断即可。
- 扩展的 service worker 随时会被回收，提醒精度取决于浏览器什么时候唤醒它。
  后端是一个常驻进程，到点就推。
- 通知从「浏览器通知」变成「Windows 系统通知」：不依赖浏览器开着，点击后用
  默认浏览器打开复习页面就行。

## 组成

| 模块 | 职责 |
|------|------|
| `app/review/constants.py` | 阶梯间隔、配额、免打扰默认值等可调参数 |
| `app/review/schedule.py` | 纯函数：阶梯推进、到期挑选、免打扰时段、退避 |
| `app/review/store.py` | SQLite 落库（与生词本同库 `user.db`） |
| `app/review/notifier.py` | Windows 系统通知（`windows-toasts`） |
| `app/review/example.py` | 例句生成（可选 LLM，回落到收藏时的上下文） |
| `app/review/service.py` | 同步队列、跑一轮调度（每日一次批量提醒）、组装会话、评分、组卡片 |
| `app/review/scheduler.py` | 后台常驻循环（随 FastAPI 起停） |
| `app/review/api.py` | REST 接口 + 复习页面路由 |
| `app/review/static/review.html` | 会话式复习页面（复习 + 配置） |

## 艾宾浩斯阶梯

间隔阶梯（分钟）：`5 / 30 / 720 / 1440 / 2880 / 4320 / 7200 / 11520 / 17280`
（5 分钟 → 30 分钟 → 12 小时 → 1 天 → 2 天 → 3 天 → 5 天 → 8 天 → 12 天）。

早期只保留三档：比 12 小时更细的小档都会因为「今天复习过的词当天不再出现」
塌缩成「明天」，级数花在天级部分（1 / 2 / 3 / 5 / 8 / 12 天），不再一放就是
一周半。

- 单词纯靠时间往上爬（`auto`）。
- 复习页面上的「记得 / 忘了」只做微调：**记得跨两级**（并多等一级），**忘了退
  一级**（不会掉到第一级以下）。
- 走完整个阶梯后按 `graduated_action` 处理：`stop`（默认，停止推送）或
  `restart`（清零重新开始）。

## 队列从哪来

只有**至少复习过一次**的生词才进队列——刚收藏、还没看过的词没有记忆曲线可排。
扩展的闪卡评分会调 `POST /api/vocabulary/{word_id}/review`，写入
`last_reviewed_at` 与 `review_count`，后端据此挑词。

## 推送与配额

**一天最多提醒一次**：到点的词组成一个批次，合成**一条**通知推出去，不再一个词一条
地刷通知中心。

- 每天最多 `max_per_day`（8）**个词**：一批只推「今天剩余额度」个，超额的词推迟到
  今天 23:59:59——明天零点后优先补上，同时会话里它们仍然算"今天到期"；
- 当天已经提醒过之后，**不再发第二条**：晚些到期的词照样进当天的复习会话（受剩余
  额度限制），只是不再叮第二次；
- 免打扰时段（默认 23:00–08:00，可跨零点）内**不发通知，也不改词的到期时间**——
  唤醒点由 `get_next_wakeup_at` 直接推到窗口结束。免打扰只挡通知，不挡复习：用户
  自己打开复习页面，照常能看到并复习到期词；
- 推送失败按指数退避（2 分钟起步，30 分钟封顶），**不占用**这个词在阶梯上的位置，
  也不计当天额度——下次还会再推。

## 复习会话

通知点击（或直接打开 `/review`）进入的就是一个**会话**：有序词表 + 第一张卡片，
一张张复习到完成。队列由页面自己拿着走，服务端不存会话状态——刷新页面、开两个
标签页都不会把队列走丢或串台。

- `auto`（通知点进来、打开页面）：上次提醒还没评分的词 + 今天到期且今天没复习过
  的词，受今天剩余额度限制——这就是"今天要复习的量"；
- `manual`（页面上的「立即复习」）：同样这两类，但**不受额度与免打扰限制**；不足
  一天配额时用即将到期的词补齐，补齐的词在页面上打「提前复习」标；
- 今天已经复习过（评过分）的词，当天不再进任何会话——"一天一轮"，刚复习完不会
  又被塞回来。

## Windows 通知

用 `windows-toasts`（WinRT 的 Python 封装）弹通知，并设置 `launch` 为**协议
激活地址**：

```xml
<toast launch="http://127.0.0.1:4080/review" activationType="protocol">
```

点击通知 → 系统用默认浏览器打开复习页面 → 直接进入当天的复习会话。通知标题是
"今天有 N 个单词要复习"，正文预览前几个词。地址是固定值（`REVIEW_PAGE_URL`），
不做成配置项——一天只有一条批量提醒，不存在"点哪个词打开哪个地址"的问题；
页面仍兼容旧的 `?word={id}` 深链（单卡）。

通知归属的 AUMID 默认借用系统自带的 `Microsoft.WindowsPowerShell`（保证任何
Windows 机器上都能弹出来）。想换成自己的应用名，设环境变量
`MDX_REVIEW_TOAST_AUMID`。

非 Windows 平台（或没装 `windows-toasts`）上会安静降级：状态接口里
`notification_available` 为 `false`，调度按「推送失败」处理并退避；页面本身仍是
可靠的复习通道。

## 复习页面

`GET /review`——一个自带的单文件页面（`app/review/static/review.html`），不依赖
浏览器扩展。视觉是苹果式极简：浅灰底、白色大圆角卡片（阴影分层、无描边）、
大字号单词、圆形操作按钮；深色模式自动跟随系统。

- 三态主区域：
  - **空闲**：居中大按钮「立即复习」+ 状态文案（今天还有几个词 / 今天的复习
    已完成 / 下次提醒时间 / 计划为空）；
  - **会话中**：顶部进度（第 k / N 个 + 进度条 + 「退出」）→ 单词居中（位置
    固定不动），朗读喇叭紧贴单词右侧，音标在单词下方居中 → 编号词典释义
    （中文为主、英文释义弱化；有释义时不再重复收藏时带的翻译）
    → 「词典释义」例句框 → 圆形 ✕（忘了）/ ✓（记得）锚定在卡片底部；
    卡片有最小高度，长短不同的词条之间不会忽高忽低；
  - **完成**：🎉 + 本次复习数 + 「再来一组」；
- 例句**预加载**：会话开始后就按队列顺序在后台生成（页面保持最多 3 个请求
  在飞，LLM 一次约 2-3 秒），切到某个词时例句和固定搭配通常已经在了；
  没配 LLM 或调用失败就退回收藏时的上下文，不影响复习。生成结果同时进
  页面缓存和后端词条缓存（`last_example` 等列），`/api/review/rate` 返回
  的下一张卡片也可能直接带上例句；
- `GET /review` 响应带 `Cache-Control: no-cache`：页面是单文件（HTML + CSS
  + JS 全在里面），不带这个头的话浏览器会启发式缓存，改一次页面旧 JS 能
  活几个小时——表现为「接口返回是对的，页面还按旧代码渲染」；
- 状态磁贴：待复习、今日已复习、计划总数、**下次提醒**。注意“下次提醒”不是
  某个词单纯的 SRS 到期时间——被每日配额推迟的词，到期时间只是今天
  23:59:59 的占位值；`get_next_notify_at()` 会把“今天已经提醒过 / 额度用完 /
  免打扰时段”这些闸门都算上，给出真正会响下一次的时刻；
- 页面上没有任何手动动作按钮——测试通知 / 同步队列 / 立即推送 / 清空队列都不
  再暴露给用户（端点保留，供调试）；
- 配置在**右上角齿轮**弹出的设置层里：iOS 风格开关（开启复习提醒）、每天复习
  词数、走完阶段后的处置、免打扰时段（只挡通知）、LLM 例句开关与
  base_url / api_key / model。通知点击地址是固定值，不占配置项。

## 接口

| 方法 | 路径 | 说明 |
|------|------|------|
| `GET` | `/api/review/status` | 可复习词数、今日已复习/已提醒、下次到期、通知是否可用 |
| `GET` | `/api/review/config` | 读取配置 |
| `PUT` | `/api/review/config` | 按字段合并更新配置 |
| `GET` | `/api/review/session?mode=auto\|manual` | 组装一次复习会话（词表 + 第一张卡） |
| `POST` | `/api/review/example` | 按需生成（并缓存）一个词的例句 |
| `GET` | `/api/review/card?word_id=` | 取一张复习卡片（不传则返回下一个待评分词，兼容旧行为） |
| `POST` | `/api/review/rate` | 记录评分 `{word_id, kind, next_word_id?}`，返回下一张卡片 |
| `POST` | `/api/review/notify-test` | 发一条测试通知（内部/调试，页面上已无入口） |
| `GET` | `/api/review/pending` | 待评分的词列表 |
| `GET` | `/review` | 复习页面 |
| `POST` | `/api/review/sync` | 用生词本对齐复习队列（内部，调度器用） |
| `POST` | `/api/review/tick` | 立刻跑一轮调度（内部/调试；免打扰与配额照常生效） |
| `DELETE` | `/api/review/queue` | 清空复习队列（内部/调试，不动生词本） |

## 例句

例句是可选的加分项，**任何一步失败都不影响推送**：

1. 配了 LLM（`base_url` + `model`）且 `generate_example` 为真 → 调
   OpenAI 兼容接口生成例句 + 中文翻译 + 固定搭配（每个搭配带中文意思），
   角度按推送次数轮换
   （日常对话 / 邮件 / 技术博客 / 影视对白 / 学术写作 ……），避免连续两次
   同义改写；
2. 没配 LLM 或调用失败 → 退回收藏这个词时抓到的上下文句子；
3. 上下文就是词本身（GoldenDict 常这样）→ 通知正文用兜底文案。

`base_url` 里含 `openrouter.ai` 时，请求会自动带上 `HTTP-Referer: https://pi.dev`
和 `X-Title: pi` 两个归属头（OpenRouter 官方推荐，其他提供商不带）。

代理从标准环境变量读（`MDX_LLM_PROXY` > `HTTPS_PROXY` / `https_proxy` >
`HTTP_PROXY` / `http_proxy`），但**不让 httpx 自己解析**：这台机器的
`NO_PROXY` 里带方括号 IPv6（`[::1]`），httpx 会在构造 Client 的阶段直接抛
`InvalidURL: Invalid port`——请求根本发不出去（`app/eudic.py` 里记录了同一个
坑）。自己取出代理 URL 显式传给 `Client(proxy=...)`，并关掉 `trust_env`。

搭配在接口里统一是 `[{"text", "chinese"}]`：`text` 是搭配，`chinese` 是它的
中文意思——只背搭配不知道意思等于没背。老库、老输出里的纯字符串会在读出来时
补齐成 `chinese: ""`，页面照常显示搭配本身。

## 存储

与生词本同库（`user.db`），三张表：

- `review_schedule`：每个词的进度（阶梯、到期时间、推送次数、例句、最近评分
  时间……）。`last_rated_at` 是后加的列，老库会在启动时自动补上
  （`store._migrate_db`，沿用生词本那边的迁移写法）；
- `review_stats`：每日推送配额统计
- `review_settings`：配置（JSON）与上次同步时间
